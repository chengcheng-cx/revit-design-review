# M0 architecture

M0 proves one end-to-end workflow in Revit 2026:

1. Select model elements.
2. Create a review with a short title.
3. Store element `UniqueId` values and the active viewpoint in a local SQLite database.
4. Open the latest review, restore its saved view, select surviving elements, and zoom to them.

## Boundaries

- Single-user and local-only.
- Revit 2026 only.
- Existing views are reused; M0 does not create dedicated review views.
- 3D camera orientation and active section box are stored in Revit internal coordinates and units.
- Linked-model element selection, comments, status editing, browser UI, clash detection, markup, and BCF are deferred.

## Dependencies

```text
RevitDesignReview.Core
        ↑
RevitDesignReview.Data
        ↑
RevitDesignReview.Revit2026
```

`Core` and `Data` do not reference the Revit API and can be tested on GitHub-hosted runners.
The Revit adapter is built locally against an explicitly supplied Revit installation directory.
Autodesk's Revit 2026 assemblies can emit `MSB3277` framework-reference conflict diagnostics during
resolution; the adapter treats that known Autodesk/.NET binding diagnostic as a message, not a build warning.

## Local data

Databases are stored under:

```text
%LOCALAPPDATA%\RevitDesignReview\projects\{project-hash}\reviews.db
```

The hash is derived from Revit Project Information `UniqueId` and the model path. No review database is written into the RVT file.
